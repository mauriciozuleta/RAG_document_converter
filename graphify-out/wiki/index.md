### Extraction behavior

All PDFs now use page-aware extraction. `document_extract.py` preserves raw text, source-line bounding boxes, page sizes, a spatial text view, and source page numbers. Reading order remains a pdfminer heuristic; the original coordinates are retained for verification. Repeated values, captions, identifiers, headers, and footnotes are not deleted. Vertical text and text inside PDF figures are included in layout analysis.

HTS detection adds chapter context and supplementary physical table rows. Its authoritative content is now the spatial view, preserving indentation and superscripts. The supplementary `table_rows` are explicitly not normalized tariff records; wrapped cells and inherited values require review. The previous flattened labeled-row rendering is no longer the primary output.

Schema version 2 keeps `title` and `sections`, adds `source_lines`, `raw_text`, `layout_text`, `warnings`, and `review_required`. Markdown uses variable-length fenced text blocks to preserve layout and safely display literal Markdown from source documents. Per-page warnings appear in both Markdown and JSON and in conversion logs. General document-type selections are recorded as metadata rather than forcing destructive heading heuristics.

Empty/sparse text, unresolved glyphs, embedded images, and graphical rules are flagged. Optional local PaddleOCR PP-StructureV3 now processes scanned text and table layout. The GUI disables OCR by default; enable it only for sparse/unreadable-page fallback. The CLI defaults to native extraction and accepts `--engine paddle`. Models download on first use, then inference runs locally on CPU. Formula, chart, and seal recognition are disabled. Model-derived output must be checked against native evidence and original pages. This pipeline is a conservative local preservation format, not a guarantee of semantic reconstruction for arbitrary tables, mathematics, or diagrams.

Run `python -m unittest -v`. Set `HTS_TEST_PDF` to the supplied 2026 Revision 20 PDF for the real Chapter 1 and Chapter 2 checks. Tests generate small real PDFs without additional test dependencies. `verification/layout_verified_sample.md` and `.json` are local comparison artifacts.

### Running with OCR

Use `launch_app.ps1` to start the isolated `.venv` environment. Recreate it with `python -m venv .venv` and `.\.venv\Scripts\python -m pip install -r requirements-ocr.txt`. PaddleOCR 3.7.0 and PaddlePaddle 3.3.1 are pinned. The page field accepts `911-920` or `1,3-5`; blank processes all pages. The corresponding CLI flag is `--pages`.

`paddle_extract.py` renders one page at a time, applies PP-StructureV3, and retains native content plus structured model JSON. `content` becomes model Markdown, `native_content` preserves the prior extraction, and `ocr_result` includes recognition/table data. OCR coordinates are image pixels; native coordinates remain PDF points. Markdown includes model output followed by fenced native text for comparison. Extracted model images are stored in an adjacent `_ocr_assets` folder, which must accompany Markdown when moving files. OCR failures abort the conversion rather than silently falling back.

### PDF table exports

Choose Tables CSV or Tables Excel in the output-format controls. These modes now try native ruled-table extraction first; OCR fallback is optional for sparse/unreadable pages. Recognized HTML tables become one UTF-8 CSV file per table or one Excel workbook with a worksheet per table, named by source page and table number. Excel stores cells as text to preserve leading zeros and literal formulas, and retains merged cells. CSV places merged content in the top-left cell with blank continuations; import CSV columns as text in spreadsheet software to preserve identifiers. OCR recognition still requires comparison with the source PDF. No recognized tables produces an error instead of an empty success. Standalone image input is not supported. CLI equivalents are `--format csv` and `--format xlsx`; Excel uses openpyxl already supplied by the OCR environment. There is no interactive table preview in this version.

Cross-page continuations remain separate. Import identifiers as text in spreadsheet software.

### Fast native table conversion and resume

CSV/Excel conversion now enters `table_conversion.py` before general document extraction or HTS detection. It processes selected pages with pdfminer, detects continuous ruled table bodies using `native_tables.py`, and assigns native characters by cell coordinates. No document-specific coordinates or headings are assumed. Native extraction does not infer borderless tables or reconstruct separate/merged headers: review the PDF and per-page report. Multiline cells, repeated rows and leading zeros remain text. Native CSVs contain the detected cells without invented column headings.

OCR is off by default in the GUI. Enabling Allow OCR for scanned / unreadable pages (or CLI `--engine paddle`) permits fallback only when no native table is found and page text is sparse or has unresolved characters. Digital pages without detected tables are reported for review, not sent through OCR. This is a text-quality heuristic; mixed pages with embedded scanned tables and plentiful native text may require manual review. JSON/Markdown also use optional OCR only for sparse/unreadable pages.

Table conversions save page checkpoints under `.table_checkpoints/`, keyed by source SHA-256, extraction version and OCR policy. Rerunning the same PDF/output folder resumes completed pages automatically. CSVs are saved page by page; Excel is assembled at the end from checkpointed tables. A JSON review report records page methods, missing tables and native-header limitations. Logs show page count, native/OCR/cache method, elapsed time and estimated remaining time. Estimates during OCR/model initialization may vary. Ordinary JSON/Markdown conversions do not use the table checkpoint cache.

Validation on the supplied 94-page CARICOM PDF: native app CSV conversion completed in about 11 seconds; all 3,535 rows matched the prior verified export cell for cell. Cached processing completed in about 0.2 seconds. These timings apply to this PDF and machine, not all layouts.
