# Three-worker memory policy (2026-10-07)

The UI offers up to three GPU OCR workers; the default remains two. `memory_budget.py` measures current available physical RAM and NVIDIA free VRAM on every launch, including cached launches. It budgets the largest measured per-process peak working set and CUDA reserved/allocated peak with 25% growth allowance, minimum 2.5 GiB each per worker, plus shared reserves of 3 GiB RAM and 1 GiB VRAM. This estimate limits benchmark admission and the selectable worker count; a successful three-worker benchmark is required before the UI offers three. No fitting validated worker produces an explicit error.

Memory telemetry, budgets, and maximum workers are saved in the startup profile. `ocr_parallel.choose_workers` rechecks memory before creating the conversion pool, caps the request and logs reductions. The bounded CPU crop queue and ordered merge support three workers unchanged. Cached throughput results never bypass fresh availability checks. Relaunch after freeing memory to refresh options; use Rebenchmark to retry failed tests. Large document pages may exceed the synthetic fixture's memory estimate.

# Current automatic launch and worker policy (2026-10-07)

`app_bootstrap.py` verifies dependencies, prepares models and benchmarks CPU/one-GPU/two-GPU OCR. `launch_app.ps1` locates supported 64-bit Python or installs it via winget. NVIDIA GPUs are selected by UUID; Blackwell uses cu129, older supported hardware cu126. Profiles/logs stay in ignored `.runtime/`; `-Rebenchmark` repeats calibration, `-CpuOnly` explicitly selects CPU, and `-SetupOnly` avoids launching the UI.

Two GPU workers are the default when the two-worker test passes, even if one worker scores faster. A failed two-worker test allows a visible one-worker fallback only if its test passed. Both failing raises an error. Static free-RAM restrictions and the former single-GPU-worker cap are removed. Historical single-worker policy descriptions below are superseded.

`inline_recovery.py` prepares GPU crops in the CPU coordinator using `image_ocr.prepare_images`, feeds bounded tasks to persistent model processes, and merges results at their source positions. Successful recovery caches are reused. The queue passes cropped image paths; GPU workers do not reopen the original PDF when prepared crops are supplied. UI shows the selected hardware and worker configuration. Existing running jobs are unchanged until restarted.

Benchmark results describe small synthetic images, not full-document performance guarantees. The local RTX 3060 passed all three tests; 41 unit tests passed with two external-fixture skips.

### Extraction behavior

All PDFs now use page-aware extraction. `document_extract.py` preserves raw text, source-line bounding boxes, page sizes, a spatial text view, and source page numbers. Empty/sparse text, unresolved glyphs, embedded images, and graphical rules are flagged. Optional local PaddleOCR PP-StructureV3 now processes scanned text and table layout. Formula, chart, and seal recognition are disabled. Model-derived output must be checked against native evidence and original pages. This pipeline is a conservative local preservation format, not a guarantee of semantic reconstruction for arbitrary tables, mathematics, or diagrams.

### Running with OCR

Use `launch_app.bat` or `launch_app.ps1` for automatic environment setup, benchmarking and device selection. The GUI runs `conversion_worker.py` in a separate Python process through `conversion_jobs.py`. Native Paddle errors or abrupt exits cannot directly terminate the Tk process. Cancel terminates the worker process tree; closing a running app cancels before exiting. The progress bar no longer overlaps the conversion controls. Batch output names include an index and source filename to avoid chapter-number collisions.

### Fast native table conversion and resume

CSV/Excel conversion now enters `table_conversion.py` before general document extraction or HTS detection. It processes selected pages with pdfminer, detects continuous ruled table bodies using `native_tables.py`, and assigns native characters by cell coordinates. No document-specific coordinates or headings are assumed. Native extraction does not infer borderless tables or reconstruct separate/merged headers: review the PDF and per-page report. Multiline cells, repeated rows and leading zeros remain text. Native CSVs contain the detected cells without invented column headings.

OCR is off by default in the GUI. Enabling Allow OCR for scanned / unreadable pages (or CLI `--engine paddle`) permits fallback only when no native table is found and page text is sparse or has unresolved characters. Digital pages without detected tables are reported for review, not sent through OCR. This is a text-quality heuristic; mixed pages with embedded scanned tables and plentiful native text may require manual review. JSON/Markdown also use optional OCR only for sparse/unreadable pages.

Table conversions save page checkpoints under `.table_checkpoints/`, keyed by source SHA-256, extraction version and OCR policy. Rerunning the same PDF/output folder resumes completed pages automatically. CSVs are saved page by page; Excel is assembled at the end from checkpointed tables. A JSON review report records page methods, missing tables and native-header limitations. Logs show page count, native/OCR/cache method, elapsed time and estimated remaining time. Estimates during OCR/model initialization may vary. Ordinary JSON/Markdown conversions do not use the table checkpoint cache.

### Two-pass inline recovery (current behavior)

`inline_recovery.py` first records native text plus coordinate-based recovery flags for image regions, textless vector figures, and sparse/unreadable pages. Nested images are inspected; overlapping/touching image tiles are grouped. Only after all selected pages have been inspected does the recovery pass load OCR and visit flagged regions. Flags have page/region IDs, bounding boxes, pending/converted/unresolved states and candidate image-sequence IDs across consecutive flagged pages. Sequence IDs are navigation aids, not a claim that consecutive images form one semantic table. Every page is inspected independently; native text resumes at its spatial position when an image ends. Reading order is top-to-bottom, then left-to-right and remains a heuristic for complex columns.

JSON and Markdown now render the same ordered native/OCR blocks, fixing an earlier Markdown path that could omit recovered content by preferring native layout_text. Native evidence remains in JSON metadata. No recognized image content is required from a separate user-facing file. CSV/Excel combine native tables and OCR content in spatial order within each page's CSV or worksheet; non-table OCR prose occupies text rows in that same export. Page boundaries remain explicit; cross-page tables are not silently joined. Diagnostic model artifacts and reports remain supporting files. Previously generated sidecars are not deleted.

Empty or failed OCR leaves a visible OCR UNRESOLVED marker at the affected position, and processing continues. OCR disabled leaves OCR PENDING markers. Flags and a native-pass snapshot are saved before model loading. Recovery caches are keyed to the PDF hash, region geometry and policy; successful regions are preserved after partial failure and reused on retry. Table native checkpoints use v3-inline. Remaining flags provide precise locations for the user's subsequent original/output comparison. Raster and textless-figure detection does not guarantee detection of every PDF visual encoding or recognition accuracy.

### Parallel CPU OCR

The GUI now offers OCR workers 1 or 2 (requests 2 by default). CLI `--ocr-workers 2` and API `ocr_workers=2` enable the same behavior; CLI/API default to 1. The recovery coordinator permits two workers only with at least 12 GB available physical RAM, at least eight logical CPUs and two flagged pages. Otherwise it logs a fallback to one. This is a conservative starting threshold, not a guarantee against changing memory pressure.

Each spawned process handles one flagged page at a time, reuses its own Paddle pipeline (four CPU threads), and visits that page's image regions sequentially. At most two tasks are in flight. Results are consumed as they finish, but update their original page objects so exported document order stays intact. Cached results are reused. The parent alone updates the flag manifest and global completed count; worker failures remain visible as unresolved flags. The existing GUI process-tree cancellation covers spawned workers. Native extraction remains serial.
